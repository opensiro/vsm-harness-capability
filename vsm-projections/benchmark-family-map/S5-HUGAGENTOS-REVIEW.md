## Function-first mapping

The direct fit comes from the exercised durable policy-change and return path rather than from the existence of `AGENTS.md` or an instruction API:

```text
authorized project-rule write
        ↓
new durable rule content is persisted with revision protection
        ↓
stale overwrite is rejected
        ↓
ORM state is expired
        ↓
native project-context assembly rereads project instructions
        ↓
`project_instructions` equals the newly saved policy
        ↓
later project-agent construction has a returned authoritative context input
```

At the declared HugAgentOS project recursion, the current Profile requires an identity- or ultimate-policy-level decision path, legitimate authority, ownership/enforcement separation, and return into subsequent operation. The evidence supports the narrow descriptive mapping:

1. **policy level** — the canonical assessment establishes project-root instructions as durable goals, work rules, quality expectations and operating boundaries for later project operation;
2. **legitimate authority** — the exercised tool is project-bound and authorization-checked; a later write after project deletion is rejected;
3. **actual enactment** — the test changes the durable rule content to `# Rules\nTest first.` and verifies persistence plus revision behavior;
4. **return path** — after expiring ORM state, native project-context assembly returns the changed instructions rather than a stale in-memory value;
5. **ownership/enforcement separation** — persistence, revision checks, permissions and context assembly enforce/transport the policy state but do not by themselves establish which actor semantically chose the rule content.

That is stronger than a static policy file, parser, CRUD schema or permission test because one changed authoritative rule state is written and then recovered through the native context path intended for later project-agent operation.

## Ownership boundary

The canonical Index assessment independently classifies HugAgentOS S5 as `A(P)`:

- base `A` mode: the model-driven `/init` actor semantically chooses an exact durable project-rule update and persists it;
- parent `P` mode: an authorized project editor/admin directly owns the authoritative policy edit.

The admitted acceptance test does **not** execute `/init` through a model turn and therefore does not itself demonstrate autonomous `A` ownership. It also should not be read as a production record of a human editor deciding the exact rule. Its evidentiary role is narrower: it demonstrates the native durable-policy enactment and return machinery at the exact canonical revision.

Accordingly, direct S5 relevance is credited to the canonical HugAgentOS project boundary, while ownership state remains an independently owned Index fact.

## Evidence limitation

The observation is a controlled first-party acceptance-test witness, not production history or a downstream task result.

The test stops after `build_project_ctx(...)["project_instructions"]` returns the new rules. It does not create a later model turn and measure changed behavior under `Test first.`. The canonical implementation and assessment establish that project instructions are subsequently injected into project-agent prompts, but that surrounding mechanism evidence is not a second empirical result.

Therefore the narrow direct claim is:

```text
changed authoritative project policy was persisted and returned through native project-context assembly
```

not:

```text
a public downstream task demonstrated behavioral compliance with the changed policy
```

## Relationship to DotCraft, Ouroboros and the S5 reopen gate

HugAgentOS is structurally closer to the live DotCraft S5 witness than DotCraft is to the frozen Ouroboros repository-history witness:

- **DotCraft**: parent-authored Agent Profile is selected for a native thread, resolved into the persisted runtime contract and retained after source-profile removal;
- **HugAgentOS**: durable project instructions are changed through a native authorized tool, persisted with revision protection and returned by later native project-context assembly;
- **Ouroboros**: immutable repository-history witness contains a parent-governed constitutional/runtime policy change, executable return and later canonical lineage.

DotCraft and HugAgentOS therefore share a useful descriptive shape: durable canonical policy -> native enactment -> persisted/returned runtime state, with neither controlled test executing a subsequent public task outcome.

However, they do **not** form a materially matched primary comparison cell under `BASELINE.md`. The evidence does not hold constant a common evidence family/version, task or intervention protocol, evaluator, execution environment, or adaptation/reset policy. The policy objects also differ materially: a DotCraft Agent Profile is compiled into a thread runtime contract, while HugAgentOS project instructions are reread into project context. Treating these as one matched benchmark/evidence family would manufacture comparability from structural analogy.

Therefore the frozen reopen condition remains unsatisfied for primary-baseline purposes:
